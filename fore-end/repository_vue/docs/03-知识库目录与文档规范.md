# 知识库目录与文档规范

## 1. 当前知识库目录

当前知识库目录固定为：

```text
P:\AIprogect\repository\fore-end\repository_vue\knowledge
```

当前已存在的文件包括：

- `KNOWLEDGE.md`
- `知识库标记.md`

## 2. 文档应该放在哪里

所有要参与知识库问答的 Markdown 文档，都放进：

```text
knowledge/
```

不要继续放在项目根目录，原因：

- 避免把 `README.md` 之类无关文件混进知识库
- 便于后续做分类和索引
- 便于后续迁移到真正的向量库

## 3. 推荐的知识库目录结构

```text
knowledge/
  ├─ 01-接口说明/
  ├─ 02-字段说明/
  ├─ 03-页面业务规则/
  ├─ 04-流程文档/
  ├─ 05-测试标记/
  └─ KNOWLEDGE.md
```

如果当前后端只扫描一层目录，那么现阶段先扁平放置即可；如果后续要支持子目录，需要同步改后端扫描逻辑。

## 4. 文档内容怎么写更适合知识库

建议规则：

- 一个主题一个文件
- 文件名直接体现主题
- 标题层次清楚
- 少写无关闲聊
- 一段文字只描述一件事
- 尽量把关键字段、接口名、枚举值写全

## 5. 推荐写法示例

### 接口说明

```md
# 用户档案查询接口

## 请求路径
`/api/user/profile`

## 请求参数
- userId: 用户 ID

## 返回字段
- userName: 用户姓名
- age: 年龄
```

### 字段说明

```md
# PLAN_KIND 字段说明

## 作用
用于区分方案类型。

## 枚举值
- ZL: 治疗方案
- FC: 复查方案
- SS: 膳食方案
- QT: 其他方案
```

## 6. 当前阶段的文档大小建议

对于第二阶段的向量检索实现，不建议一开始就放特别大的单文件。

更合适的做法：

- 拆小文档
- 用多个主题文件代替一个超大文件
- 保持每个文档聚焦一个主题

原因：

- 当前向量检索仍是轻量实现
- 超大文档会让切块、embedding、排障都更难
- 后续命中结果也更杂

## 7. 验证知识库文档是否生效的方法

最稳的做法是加入唯一标记：

```md
# 测试标记
本地知识库验证口令：RAG-CHECK-20260430-ALPHA
```

然后问：

```text
知识库验证口令是什么？
```

如果回答能命中该内容，并显示来源文件，就说明这份文档已经参与知识库。
