# 测试与排障手册

## 1. 基本启动顺序

建议启动顺序：

1. 启动 Ollama
2. 确认模型已安装
3. 启动 Spring Boot 后端
4. 启动 Vite 前端

## 2. 基础检查项

### 2.1 检查 Ollama 是否可用

```powershell
curl http://127.0.0.1:11434/api/tags
```

至少应看到：

- `deepseek-r1:7b`
- `bge-m3:latest`

### 2.2 检查前端代理

前端本地开发时，`/api` 会代理到：

```text
http://127.0.0.1:8080
```

如果后端没启动，前端会直接请求失败。

### 2.3 检查知识库目录

确认目录存在：

```text
P:\AIprogect\repository\fore-end\repository_vue\knowledge
```

确认里面确实有 `.md` 文件。

## 3. 三种模式的测试方法

### 3.1 普通对话

问题示例：

```text
你现在是什么模型？
```

预期：

- 能拿到普通回答
- 不展示知识库来源

### 3.2 固定文档模式

问题示例：

```text
知识库验证口令是什么？
```

预期：

- 命中 `知识库标记.md`
- 展示来源文件
- 能看到唯一口令

### 3.3 向量知识库模式

问题示例：

```text
知识库方案里第二阶段推荐做什么？
```

预期：

- 返回答案
- 展示来源
- 来源项有 `score`

## 4. 当前已知问题

### 4.1 `rag-simple` 成功但 `rag` 失败

这说明：

- 前端没问题
- 聊天模型链路没问题
- 知识库目录读取也没问题
- 问题集中在 embedding / 向量检索链路

### 4.2 向量知识库返回 502

当前已知现象：

- 前端请求 `/api/ai/rag`
- 后端返回 `502`
- 说明异常发生在后端向量知识库逻辑中

当前已经做过的优化：

- 增加了文档 chunk embedding 内存缓存
- 增加了 `max-chunks` 限制
- 增加了更明确的配置校验与错误提示

### 4.3 修改配置后不生效

最常见原因：

- 改了 `application.properties` 但没有重启后端

## 5. 快速定位顺序

如果再次失败，按这个顺序查：

1. `rag-simple` 是否仍然正常
2. `curl http://127.0.0.1:11434/api/tags` 是否正常
3. `bge-m3:latest` 是否确实存在
4. 后端是否重启过
5. `knowledge` 目录里是否放了过大的单文件
6. 前端错误提示里是否出现具体 detail

## 6. 当前最有效的降复杂度办法

如果向量知识库还不稳定，优先做：

- 暂时移出超大的 Markdown 文件
- 只保留 1 到 3 个小文档测试
- 先验证向量检索逻辑是否能跑通

例如：

```text
knowledge/
  ├─ 知识库标记.md
  ├─ Ollama项目接入接口说明.md
  └─ 项目中使用本地知识库RAG接入方案.md
```

不要先拿超长总文档做第一轮向量排障。
